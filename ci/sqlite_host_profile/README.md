# Read-only hosted target inventory

This is a separate source-only descendant of the reviewed eb71791 kernel/bootstrap component. Its workflow uses the original Linux artifact from run 35413241936, job 105816829953, artifact 10574998488, bound to public source 1cd7842c1da4f327b568065dd159c67e7bd0c92b and merge/build abf73b82beb6d2acc59b9ab9c37f9f1bb768d8c6. The original artifact and every prior failed/passing cohort remain unchanged.

The new run inventories a fresh ubuntu-latest host. It cannot reconstruct or claim the original host's interpreter, SQLite or kernel. The actual new runner image label/version and GitHub source/run/attempt are retained. Python remains the original workflow's 3.12 selector and uv remains 0.9.26; their actual resulting executable identities are collected rather than assumed.

Before installing anything from the original wheel, the workflow checks the whole original ZIP's 13,365,053-byte size and SHA256, its native wheel's 8,730,195-byte size and SHA256, the 12,400,392-byte runtime and the retained original identity report. It reads ZIP members without executing them and rejects ambiguous/traversal names, symlinks, encryption and size overflows. Only the exact native wheel is materialized. API authorization is used for the one fixed GitHub artifact endpoint; the separate signed-storage request carries no token, and neither credential nor signed URL enters a report.

The source checkout is fixed to 1cd. Its pyproject.toml, uv.lock and original native-wheel workflow must match the independent byte/Git-blob pins. `uv sync --frozen --extra dev --python 3.12 --no-install-project` installs that lock's dependencies, then `uv pip install --no-deps --force-reinstall` installs the already verified original wheel. The omitted project installation avoids rebuilding or importing Guard from the source checkout. uv's no-install-project option retains the project's dependencies; the exact 0.9.26 implementation was read at [its tagged CLI source](https://github.com/astral-sh/uv/blob/0.9.26/crates/uv-cli/src/lib.rs).

Capture uses the resulting environment with Python isolated mode. It compares all 1,330 installed package members byte for byte with the original native wheel, including the runtime. The report keeps the old collector's installed-package digest as an original identity and labels the newly computed member manifest separately; it does not claim those are the same digest algorithm. Guard is never imported or executed. A Python audit hook refuses Guard imports and SQLite connection requests.

SQLite inspection imports the standard-library SQLite extension and calls only its version/source metadata functions. It uses NOLOAD on the already loaded extension, the previously reviewed reader source and the actual resolved relocation slots; it does not load a second SQLite image, register a VFS, load the shim or open a connection. The actual extension/SQLite file hashes, mapped executable hashes and ELF build IDs are retained, along with other mapped executable dependency images. An embedded, missing, changed or unsupported image yields an explicit unavailable result. Paths, addresses and process identifiers remain private.

The kernel inventory reads its release, base page size, GNU build ID notes, exposed BTF, available configuration and optional boot image. The bounded BTF reader compares actual function/tracepoint/field facts with the reviewed Linux 6.8 reference ABI; agreement is only structural. The running kernel's source correspondence, boot-image relationship and actual program capability remain unauthenticated. Missing source/config/BTF facts remain unavailable. No BPF syscall, feature probe, tracing operation, kernel mutation, namespace switch or privilege escalation is used. Effective capability bits and the two relevant sysctl values are static reads only.

Tool inspection runs only clang --version, bpftool version and uv --version, when present. Each child has a five-second timeout, three-second CPU bound and 64 KiB output-file bounds; reports contain parsed version fields and output digests, not raw output. No compiler job, BPF object, verifier attempt or target attachment is run. libbpf and available BPF header files are read for identities without loading them.

Only bounded JSON inventory reports are uploaded, with a 256 KiB limit per report. No original ZIP/wheel/runtime, raw BTF, raw mapping/config dump, trace, SQL, payload, tool output, token or signed URL is uploaded. The job has a 20-minute bound. It has read-only contents/actions permissions, no dispatch trigger, and no cancellation configuration. The sole trigger is a new push to the separately reviewed diagnostic branch, after the parent's source/publication checks.

The production collector has not been run during local preparation. Tests use finite byte streams, disposable inert files and injected capture/network doubles. Neither those controls nor the eventual inventory authorize a workload. Every report keeps authenticated_target_profile, timing eligibility and RSP131 qualification false. The inventory is the concrete input for the next independent source/image review and actual controller implementation; the existing kernel producer still needs a real compiled object/verifier result, retained mandatory links, through-ready capture proof and retirement/parent-reaping integration.
