## Actual held-file and object lifetime source

For write/pwrite, vector write and fsync/fdatasync, the selected vfs_write, vfs_writev and vfs_fsync_range arguments supply the actual held struct file. The producer copies inode identity while that reference is valid. It joins that held object to the same task's active SQLite marker interval and the actual syscall entry/return. A later descriptor lookup or pathname is never a substitute.

Each SQLite callback can issue several syscalls, including retries; each real syscall attempt is retained. Selected helper nesting is a bounded stack. Only the outer selected helper contributes to that syscall's returned-byte/sync accounting; nested backend work remains separate. Missing/unmatched returns, multiple independent outer helpers, incompatible syscall/helper returns or unexplained cross-helper nesting are unavailable. ERESTART* and restart_syscall are explicitly unsupported until a reviewed normalization proves the outward result.

All three alloc_empty_file, alloc_empty_file_noaccount and alloc_empty_backing_file constructors are mandatory. Their security_file_alloc interval starts a pending constructor; security_file_free can occur inside a failed security allocation before any successful file object exists. A successful file birth requires the matching constructor's successful return. A failed constructor never creates a reusable successful incarnation. The same private pointer can be reused only after an observed retirement and a distinct observed birth.

An inode cookie is assigned only from a proved held-inode observation. Its raw device/inode/pointer values stay private and are not an incarnation token. The cookie remains until __destroy_inode, including inode-cache residence after a file closes. At __fput entry a known file becomes RETIRING and required inode metadata is already saved. Tracking continues through filesystem release and nested cleanup. At source-proved final security_file_free, the saved file cookie is retired before allocator reuse; no inode is dereferenced after dput. Global retirement hooks also process known objects on kernel workers outside the workload's task tree.

Unknown file objects introduced through foreign descriptor import or an unobserved actor cannot acquire a successful birth merely because an fd or pointer appears. Access to a tracked file/inode/table by an unobserved actor invalidates ownership completeness. No extra application file reference, descriptor duplicate or injected syscall is used to stabilize identity.

## Descriptor, table and address-space lifetimes

files_struct identifies the shared descriptor table. Its replaceable fdtable array and growth generation are separate state. The descriptor model retains absent, reserved-with-null-file and installed states plus CLOEXEC; a reservation is not a usable file descriptor.

The mandatory boundaries are:

- alloc_fd / put_unused_fd: reservation and cancellation intervals.
- fd_install: actual new file argument before publication, including a proved inode binding.
- file_close_fd_locked: actual removed file under the held files lock.
- do_dup2: old destination captured at the entry that holds files->file_lock; the actual replacement file and CLOEXEC flags are retained before unlock. Its return occurs after possible filp_close, so a later slot lookup is insufficient.
- dup_fd: the actual unpublished new table is snapshotted before publication. A parent reservation whose pointer is still NULL is cleared in the copy by the kernel; cloning a parent model would be wrong.
- expand_fdtable: old/new array generation under its documented lock boundary.
- set_close_on_exec and supported close-range/unshare transitions: explicit flag and table changes. Unproved CLOEXEC-range mutation remains unavailable.
- do_close_on_exec: explicit slot retirement from its source-proved unshared exec table; it clears entries directly and bypasses file_close_fd_locked.
- close_files: final-reference table destruction and explicit retirement of every remaining slot; this also bypasses file_close_fd_locked. An ordinary put_files_struct call is not final retirement. The current source explicitly refuses a known table's final release on an unowned task and removes that pointer's old map identity; it does not claim to reconstruct that foreign thread's nested cleanup.

Initial inherited descriptors are captured only from the actual unpublished, unshared child table while its owner holds the new reference. A racing scan of a live CLONE_FILES table is forbidden. Inherited files have a typed left-censored origin and can support slot closure/reuse accounting; they cannot qualify selected SQLite I/O without a proved constructor birth. CLONE_FILES sharing uses the same files_struct identity; copied tables share the actual open file descriptions described by the snapshot. Table sharing with an unobserved task is unavailable. The reducer retains every table generation so reusing a pointer cannot replace earlier descriptor history. Held-file joins use that generation and each operation's full interval; an I/O interval crossing final table retirement is refused.

Task identity uses observed birth and actual task identity privately, not PID equality. Address-space identity is separate: threads and CLONE_VM share an epoch, copied address spaces receive a new epoch, and successful exec receives a new epoch even after PID/nonleader changes. The SQLite logical file key is the address-space epoch plus immutable shim token. Inherited live SQLite handles across an unproved fork are unsupported.

## Namespace, excluded I/O and closure

Rename/unlink hooks retain the actual held target inode cookies and operation result without reading or exporting names. Open file identity survives unlink and rename; replacement and inode destruction remain separate events. CKPT_START/DONE delimit only SQLite's checkpoint page-copy interval. WAL sync can precede START and database truncate/sync can follow DONE.

The measurement scope is successful synchronous syscall-return bytes and explicit synchronous sync outcomes attributed through the held-file boundary. Raw vector buffer contents are never read; requested vector byte counts remain unknown. Partial returns retain only their actual positive byte count. Kernel backend helper bytes and physical-device bytes are not invented.

Ordinary WAL uses writable MAP_SHARED mappings inside xShmMap. A source-proved SHM marker/held-file interval is recorded as explicitly unquantified shared-index mmap work. The final VMA may contain a larger merged range; it must contain the returned, aligned syscall range and retain the actual held file and protections. The profile explicitly binds x86_64, little-endian 64-bit pointers and 4096-byte base pages. Final VMA file-offset attribution remains unknown. This cannot qualify complete SQLite dirty-byte or physical-device accounting. Writable mappings outside that proved SHM boundary, read-only/private mappings of already selected SQLite files or inside other SQLite markers, async/fixed-file I/O, foreign imports and copy/splice paths remain unavailable. Ordinary non-SQLite read-only/private mappings stay outside this selected write/sync scope. This does not relax the existing finite model or original RSP131 acceptance; the report keeps selected synchronous scope separate from still-unqualified full attribution.

Shutdown requests the owned workload's normal close while every mandatory retirement probe stays attached. Signal delivery, task exit, final task/object retirement and parent reaping are distinct facts. The collector drains through owned file/table retirement and independent parent-reap evidence, then checks outstanding markers, syscalls, helpers, constructors, tables and file references. Only then may it detach; a deadline failure retains explicit incompleteness. Remaining inode-cache objects can be explicitly censored at the observation boundary, never falsely reported destroyed.
