**Diagnostic observation of legacy transition producers**

This prototype records process and native-client activity during the exact `baseline_rollback` phase so a new hosted run can resolve the missing retirement history. Every result remains `diagnostic_only=true`, `proof_verified=false`, `coverage_qualified=false` and `bootstrap_attestation_qualified=false`. The original retirement and qualification gates remain in control.

The historical immutable baseline is `2e672d2d950c6ec471005ddba46e49bba16dc23b`. Its actual `resident-stop` failure remains exit 2 with 33 stderr bytes and SHA-256 `6dc34d5cdd1cb07a44699a7f9a4c43b15b7239016a864fc7c40524bc18e9d9fb`. No old failed report, stop result, expected-negative verdict, candidate-restoration claim or requirement status is changed. The source review in the sibling `legacy-retirement-source-review` directory preserves the correction that the apparently stronger native stop helpers were not reachable from the compiled binary.

The observer starts in the candidate-owned `installed_transition_entry.py` before the negative probe is imported. CPython multiprocessing replays that entry as `__mp_main__` before target unpickling, so guardians and evaluators register their own ledgers. Other phases do not import the observer. The pinned baseline package and runtime files are unchanged.

Python 3.12 execution monitoring observes original function entries and returns, relevant C calls and the exact snapshot-validation exception. It does not replace any application function, `sys.setprofile` callback or thread profiler. Code-object entries catch aliases of the underlying native client and the pre-send review function. Low-level `fork_exec` and `CreateProcess` attempts are linked to observed original spawn/Popen calls and returned PIDs. This matters because the CPython POSIX `spawnv_passfds` path produced no process audit event in a real local test.

Each process writes a bounded, synchronous, private JSONL ledger using its own exclusive append descriptor. Records carry PID/start identity, executable and source digests, hashed arguments, narrow operation labels and original bounded-process completion flags. They contain no hook payloads, policy material or original argv text. Known helper spawns are observed; an absent child registration, missing seal, partial start, unbalanced call history, failed cleanup, identity mismatch, changed observer or late event leaves explicit incomplete diagnostics. The collector checks process identities/exits after the phase and does not equate the outer worker's exit with producer containment. The resource tracker does not replay the entry and therefore remains a visible coverage gap. Killed children without complete records remain unverified.

Observed native capabilities/self-test/stop verbs are descriptive enums only. Their `nonspawning_attested` flag remains false until an independent exact-artifact/source review supplies the required proof. The observer records the original `installed_identity` result and bounded execution results for that later comparison. A snapshot error is recorded with a separately observed cached-frame flag; the source name alone does not manufacture a cache-origin or no-launch conclusion.

The diagnostic object is attached after `worker_evidence`. Both `worker_evidence` and `suite_acceptance` are byte-identical to the parent commit. Removing only the observation bootstrap, attachment and optional-publication fallback restores the complete original entry and collector AST. The original lifecycle implementation, failed-start stop probe, floor/deadline contracts and native-wheel workflow are unchanged. Optional diagnostics are omitted if they alone would exceed the original aggregate bound; the original report must still pass the same validator.

- The independent observer suite passed **28 tests in 4.43 seconds**. It exercises real subprocesses and spawn interpreters, a killed child, creation before slot registration, aliases, activity in another interpreter, existing-thread profiler preservation, late activity, original failed/nonboolean cleanup, malformed records, the actual nested privacy sanitizer and all aggregate-bound cases.
- Ruff and formatting checks passed. Scoped type analysis used the hosted workflow's Python 3.12 target and reported **zero errors**; its warning count and complete output are retained in `validation.json` and the raw log.
- The eight earlier replay-counterexample failures and two monitoring-initialization failures are preserved with their source manifests. Successful later tests do not replace the original transcripts.

The synthetic ledgers are test fixtures, including intentionally malformed counterexamples. Their inventory records exact bytes and hashes; compressed files are lossless. They are not installed-artifact retirement evidence. The source and validation manifests identify the actual files tested, and `source-preservation.json` records the unchanged gate and lifecycle hashes.

The bounded local overhead witness ran **12 balanced enabled/disabled pairs**, alternating order, under the shared validation lock. Every run completed 10,000 harmless Python calls and one waited Python child with the same result. Median total process wall time was **42.20 ms disabled and 167.88 ms enabled**; the median paired increase was **123.89 ms**, ranging from 117.15 to 137.00 ms. Observer import/bootstrap alone took a median 74.69 ms. The separately measured application interval was 16.45 ms disabled versus 61.03 ms enabled. All 24 raw runs, individual subprocess timings, source hashes and the executable witness are retained. No outliers were dropped and no measurement was compensated. These are material local observation costs, not an estimate of the actual installed legacy readiness path: the synthetic workload does not construct the baseline daemon or exercise native IPC.

Instrumentation adds synchronous work inside existing deadlines. No timing equality or performance qualification is claimed, and an instrumented timeout remains a failure. The installed environment's pre-entry bootstrap, dependencies, native extensions, nonspawning native binaries and all remaining process-scope coverage need a fresh hosted witness and independent review before a distinct no-new-legacy-producers proof could be considered. Actual native IPC was not qualified locally because AF_UNIX operations are denied in this workspace. No baseline edit, Rust operation, deadline extension, threshold reduction, stop waiver or qualification credit is part of this prototype.
