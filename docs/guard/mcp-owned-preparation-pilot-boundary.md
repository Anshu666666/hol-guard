# Owned MCP preparation experiment (E)

This is a source-only Python experiment for RSP-100. The runtime default remains
the measured B behavior: request identity and current policy each derive risk
categories. Product code never imports the adapter. An explicit benchmark/test
installation selects E; the extracted public kernels retain the existing public
matching APIs, callback order and uncached fallback. No activation or performance
acceptance follows from the implementation alone.

E owns one complete strict plain finite JSON message, including RPC ID, method,
all params, key order and arguments. It separately owns all `GuardArtifact`
fields. One private category tuple supplies the approval hash and the current
policy calculation for each unchanged authority preparation. That same owned
artifact and arguments feed temporary grants, browser context and current saved
policy lookup. Categories do not enter the retained generation object and are
not reused by a later approval, catalog, current-config or saved-claim preparation.

An exact private binding detects changes to the caller's original message, the
owned message, the original and owned artifact, and the proxy's current command.
Checks run after category calculation, after each of the two live policy
callbacks, after saved-state composition, before and after an exact saved claim,
and at the final write. Changed admitted inputs fail closed without falling back
to a stale decision. Unsupported/custom/nonfinite message shapes, concurrent or
nested admission, and package requests select the unchanged B path before facts
are admitted. Package archive argument rewrites have no E generation handoff and
remain outside this candidate's selected scope.

The final existing catalog/notification drain still uses its 5 ms quiet interval.
After that fence, E uses the existing bounded `encoded_line` encoder, decodes an
owned value from those immutable bytes, compares its exact binding, and writes
those same bytes through the factored existing framing writer. A mutable alias
is never checked and then reread for execution. Key ordering, signed zero,
Boolean/integer distinctions and exact browser params enter this binding even
when approval-token normalization intentionally drops volatile browser fields.
The writer retains the 4 MiB frame ceiling, retired-stream rejection, original
absolute forwarding deadline, nonblocking backpressure, partial-write failure
handling and terminal ambiguous-write behavior. The separate inline approval
deadline is unchanged; the experiment adds no outer child timeout around human
approval waits. Once an authorized write and response complete, later mutation
of the old caller alias cannot replace that completed outcome with a new error.

The comparison codec only serializes. It never unpickles or otherwise decodes a
pickle. Its private output is never logged, stored, returned or placed in a
receipt. A strict JSON owner first excludes custom types, nonfinite floats,
non-string keys, cycles and excessive recursion. A restricted CPython protocol-4
`Pickler` then compares exact material without repeating Python container copies:
its `reducer_override` rejects custom objects before user reduction/buffer/
iteration callbacks; `fast=True` disables memoization so shared versus duplicated
equal JSON trees have the same binding. This deprecated CPython-specific switch
is an experimental limitation, not a portability assumption. Python documents
both the override and the non-memoizing switch in its
[Pickler API](https://docs.python.org/3.12/library/pickle.html#pickle.Pickler).

Each serialized binding has a separate 16 MiB cap. One process-wide nonblocking
admission lock admits at most one E request; nested/concurrent requests use B
with a cleared context. The retained request, artifact and command bindings are
each individually capped, and comparisons create bounded temporary bindings
sequentially. The complete container owner, the final decoded wire copy and the
framing encoder's parts remain additional allocations; the binding cap is not a
claim that process RSS is capped at 16 MiB. Actual route CPU and RSS measurements
must include these copies, all binding checks and final encode/decode. The finite
JSON frame bound applies to actual stdio inputs; the pre-existing programmatic
`run_session` API is not newly claimed to admit arbitrary in-memory objects under
the same input-byte bound.

The candidate gate includes full fresh-policy/browser parity, a real child pipe
oracle, mutation at both config callbacks and saved lookup, original/owned params
and command changes at the quiet barrier, mutation during final encoding, exact
saved-claim rebuilding, zero consumption on preclaim mutation, custom callback
counts, finite binding limits/cycles, and controlled-clock fallback/approval
deadline parity. These witnesses do not establish universal alias safety in
unmodified public APIs or installed, Windows, macOS, concurrency, tail or soak
qualification.
