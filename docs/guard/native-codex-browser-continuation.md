# Native Codex browser continuation

A registered Codex PreToolUse hook that receives native `review` can wait for a local browser decision. The native queue records a suspended-response continuation only when the bridge supplies a live process identity and a valid bounded wait budget. It creates a real Guard session, waiting operation, and resume record. Each live hook owns a distinct pending request; queue deduplication cannot replace another waiting process or extend its deadline. Missing, dead, or malformed waiter proof remains retry-only.

The queued Codex artifact hash is the verified Rust receipt's `request_digest`. The same digest is retained in the canonical presentation envelope. Rust request identity v3 binds the full semantic payload, source context, and acknowledged policy generation, while excluding transport deadlines, request IDs, and the documented root event/timestamp aliases. The signed local-once approval therefore authenticates the exact native request rather than a display projection. Nested arguments that the display omits remain bound. The original validated ingress home is retained with the waiting operation and used for the fresh native call; the daemon default cannot silently replace it. Changing that retained source context must still satisfy the signed Rust request digest.

For native Codex artifact Allow once, the default once selection and explicit `persist_policy=False` both grant the existing signed local-once authority after the normal approval gate. They create no saved policy. Explicit saved-policy selections keep their existing policy behavior. A renewed policy generation, changed program/control binding, or saved-policy mutation may require a new approval because the queued native request commitment no longer matches; generation-independent ordinary local approval reuse is a separate contract.

The live-decision endpoint prepares the acknowledged workspace policy before taking the shared command-control lease. It then sends the bounded original hook input through the actual native edge and validates the local typed receipt, exact snapshot generation/policy/runtime identity, queued native program/control/observation binding, and signed request digest. It uses no Python semantic reviewer or receipt-writer cache. A terminal Rust block cannot become an approved review. The original bridge identity and deadline are checked again before finalization.

This uses the existing local approval and continuation contract; it does not invoke the standalone native approval v3/v4 consume APIs.

The verified request ID, harness, artifact, native digest, workspace, and publisher are fixed across subsequent request reads; those reads cannot select another signed grant. A newly terminal record cannot skip consumption between the authenticated replay check and finalization. The existing store continuation transaction consumes the same fixed exact local-once authority and persists the resume, operation, and event records atomically while the shared command-control lease remains held. Deadline checks follow final liveness work and database finalization/lock retirement. The original bridge identity and browser deadline are rechecked after the transaction, independently of the HTTP request budget. An expired response is refused even if its approval was already consumed; this is retained as an undelivered completion rather than a late allow. Idempotent replay additionally requires authenticated consumed authority for the same exact original hook and fresh native commitment; a mutable `sent` or `resumed` status alone is insufficient. Reopening the store retains pending and consumed exact authority, but it does not waive fresh native identity or policy generation checks.

Focused source tests exercise the real queue, store, password gate, signed authority, continuation transaction, and cross-process lock exclusion with explicitly synthetic native edge results. Installed registered-launcher qualification separately witnesses the actual native review and fresh revalidation, exactly two daemon-worker `native_resident` routes, no Python process-runner semantic route, and the final persisted continuation. Local source tests do not establish installed execution or platform qualification; that evidence must come from the built wheel on supported CI runners.
