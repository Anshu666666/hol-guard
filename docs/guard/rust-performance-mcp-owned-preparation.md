# Owned MCP preparation E: completed comparison and decision

Retain optimized Python B as the runtime default. The explicit E experiment
makes one category derivation per unchanged owned authority preparation and
binds that authority to the actual forwarded bytes. All selected calls and
paired outcomes passed. Its completed source comparison nevertheless does not
justify general activation: near-limit Unicode and dense inputs miss the 30%
benefit target, several ordinary and large blocks regress, and large inputs add
material memory. The positive 1 KiB and 128 KiB observations remain part of the
result. RSP-100 stays OPEN in the retained runtime; this completed experiment is
a concrete implementation and measured selection attempt, not a renamed
completion of B's two analyses.

## Implementation and tested ownership

The [boundary contract](mcp-owned-preparation-pilot-boundary.md) describes the
private owner and exact mutation checks. Implementation commit
cabb22960afaab329f800f154d51dd69628d99ab extracts private category/hash/current-
policy kernels while preserving public matching APIs, callback order and the
uncached path. Product code never imports the adapter. The default runtime
continues B's separate category derivations for identity and current policy.
The harness-only correction is bbb1323d1d58e528cc5094d7e59ecf0aa4904579.

E owns a strict plain finite JSON message and an artifact generation. Its one
ordered category tuple supplies identity and current policy; the same owned
inputs supply temporary grants, browser context and saved-policy composition.
It checks original and owned message/artifact/command bindings at live policy
callbacks, saved-state/claim boundaries and final forwarding. A change after
admission fails closed. Every later authority preparation derives new facts;
no saved approval, policy decision or category authority crosses that boundary.

After the existing catalog drain and 5 ms final quiet interval, E encodes the
message with the existing bounded encoder, verifies an owned value decoded from
those immutable bytes, and writes those same bytes through the existing writer
kernel. It does not compare a live alias and then reread it for execution. The
writer keeps retired-stream rejection, partial-write/backpressure handling,
terminal ambiguous-write behavior and the original forwarding deadline. The
separate human approval deadline remains unchanged. A caller alias mutation
after completed execution does not replace the real child outcome with an error.

The serialize-only binding uses a restricted CPython protocol-4 Pickler with
memoization disabled. No pickle decoder exists in the experiment. Custom
reducers/containers are rejected, and private bindings never enter logs,
receipts, stored policy or benchmark output. The deprecated CPython-specific
switch remains an experimental portability limitation. Unsupported/custom/
nonfinite message shapes, package requests and busy/nested admission use B;
there is no package archive-rewrite generation handoff or selected concurrent
E route. These scope limits are material to RSP-100.

The owner-executed source gate passed 119 tests in 80.73 seconds across owned
preparation, public request facts, framing bounds, actual stdio and catalog
generation tests. It includes 96 complete fresh-authority comparisons over
allow/warn/review/block, ordinary/terminal/browser tools and scalar/container/
Unicode values. Actual child pipes verify the received params and exact one
execution; mutation branches verify no child write. Separate witnesses cover
first/second config callbacks, store callbacks, original/owned barrier and
encoder changes, current command changes, private artifact mutation, preclaim
non-consumption and exact saved-claim rebuilding. Controlled-clock tests retain
the 120-second inline budget after 45 seconds for owned, busy, unsupported and
package routes. Post-completion mutation and custom-routing callback counts
match the retained contract.

Three production modules passed basedpyright with zero errors, warnings and
notes; changed Python files passed Ruff and formatting. The final oracle-source
and failure-accounting correction passed three targeted tests in 0.47 seconds;
these overlap the earlier gate and are not 122 unique tests. Independent fixed-
revision source and harness reviews found no remaining concrete blocker after
correcting the original draft's outer deadline, post-completion check, routing
callbacks, oracle identity and failed-worker counter retention. Reviewers ran
no tests or measurements. No archived validation stdout log is claimed.

## Frozen schedule and complete attempts

The successful campaign ran from 2026-09-17 15:19:22.291774 UTC to
15:36:30.787014 UTC: 1,028.495 seconds between first/last case endpoints, including
normal inter-case gaps. Cases held the shared POSIX lock separately for a summed
1,013.989 seconds, then released it with a short fairness yield. No sample was
interrupted or replayed to improve a result.

Five independent process blocks alternated B/E order. Each block covered
1/16/128 KiB ASCII with 30 warm calls after one cold first call, plus near-limit
Unicode and dense integers with three warm calls after one cold call. Fourteen
separate profiles followed: both arms for those five shapes, near-limit ASCII
and nested records, with ten ordinary or three large warm calls. All 64 cells
and 32 paired traces completed: 1,108 accepted forwards and 1,108 progress
notifications. E recorded exactly 554 admissions, 554 category derivations,
554 completed preparations and 554 bound writes. Selected failures, fallbacks,
timeout substitutions and source drift were zero in this timed fixture scope.
The largest external client line was 4,193,908 bytes, below the unchanged
4,194,304-byte frame ceiling.

Timed parity compares the complete public result trace, forwarded IDs/order,
decision counts, notifications, catalog generations and framing/barrier
witnesses. It does not claim a comparison of every private approval hash or
persisted evidence field for every timed request. A separate source-bound public
API oracle matched all 3,008 cases for exact ordered categories, approval hashes
and full policy decisions, including the retained public optional-facts path.
The 96 private full-authority cases and adversarial actual-forward tests provide
the distinct ownership evidence; the public oracle alone is not E activation.

An earlier incomplete candidate export omitted the required
`contracts/extensions/trust-class-map.v1.json`. It failed during imports before
any public oracle or timed cell. The zero-cell failure and its environment are
retained unchanged. The successful attempt used a separate complete archive of
the exact same source/harness revision, with 4,135 tracked files and the same
schedule. No failed decision was suppressed by that correction.

## Uninstrumented route results

Positive change means slower. Values below are medians of five within-block
percentage changes and their complete observed ranges, not confidence intervals.
Client p95 uses nearest rank and excludes the cold first call. Large cells have
only three warm observations, so their p95 is the observed maximum and is not a
release tail estimate. Live process-tree CPU includes the proxy and synthetic
server from after catalog delivery through the final response, including cold
first plus warm calls; it excludes the benchmark client's CPU and cleanup. No
Rust helper is involved. Neither deliberate waits nor ownership/serialization
costs are subtracted from the actual route.

| Input | Client p95 change, median (range) | Tree CPU/call change, median (range) |
| --- | ---: | ---: |
| 1 KiB ASCII | -47.36% (-84.30% to +73.04%) | -40.00% (-47.41% to +0.74%) |
| 16 KiB ASCII | -14.75% (-81.32% to +194.32%) | -6.96% (-46.51% to +56.10%) |
| 128 KiB ASCII | -54.54% (-91.55% to -0.89%) | -9.09% (-74.09% to +2.86%) |
| Near-limit U+20AC Unicode | -9.80% (-38.45% to +56.68%) | -10.67% (-54.32% to +18.51%) |
| Near-limit dense integers | -0.99% (-32.16% to +31.12%) | -3.05% (-23.17% to +11.18%) |

The 1 KiB medians and 128 KiB p95 median clear the arithmetic 30% benefit target.
The 128 KiB latency improves in all five blocks, with CPU's worst change +2.86%.
Those observations must not be relabeled as failure of every possible narrow
E selection. They also do not establish the original complete performance gate:
1 KiB p95 regresses as much as 73.04%, 16 KiB regresses in both metrics in two
blocks, and large shapes miss 30% median benefit. Unicode's last block is
+56.68% p95/+18.51% CPU; dense integers' third block is +31.12%/+11.18%.
The shared host also varies in unchanged policy/store/receipt work, so the
large small-input improvements cannot all be attributed to removed categories.
There is no subsequent campaign selected to obtain a favorable outcome, and no
new length/content rule is inferred from these five synthetic fixtures.

Every selected E profile has one classification per warm call; B has two.
The private checks make 43 serialize-only binding calls per warm E request,
most over small artifact/command material. They replace repeated public owned
copies while retaining actual input validation. On the dense profile, the full
message copy and bindings still cost 792.08 + 873.60 ms per call; nested records
cost 1,435.45 + 876.76 ms. Large text shares immutable strings in its owned
containers, but binding/JSON/wire costs remain included. The small-input profile
makes the attribution limit concrete: 1 KiB B classification uses 0.34 ms of
32.77 ms parent CPU, far too little to explain the five-block 40% total CPU
median by itself. Profiles do not replace the alternating primary comparison.

The configured final quiet interval remains 5 ms. Its observed profile means
range from 5.13 to 5.58 ms, predominantly waiting rather than CPU. Child wait and
all existing orchestration stay in Python. Approval accept/cancel/catalog-
invalidation and separate deadline behavior are exercised by the functional
pipe tests; earlier completed child-delay, synthetic approval-delay and real
loopback HTTP controls remain in the
[source phase audit](mcp-source-benchmark-acceptance.md). This campaign does not
add live remote, human-response, installed startup or remote network measurements.

In the separate three-sample profiles, E adds 22.02 MiB worker peak for Unicode,
32.50 MiB for dense integers and 55.31 MiB for nested records; the near-limit
ASCII pair has equal observed worker peak. Tree RSS/USS is sampled after catalog
and responses, so it does not capture every transient peak or establish an
aggregate allocation bound. OS RUSAGE_SELF peak covers the worker's whole
lifetime, including imports/transients, and excludes child peaks. Ordinary
worker peak observations range about 90–121 MiB across this campaign, so no
small difference is treated as an isolated ownership allocation.

One process-wide nonblocking admission lock limits E to one active request.
Each request/artifact/command binding has its own 16 MiB serialized limit;
sequential comparison buffers, owned containers, the final decoded wire copy
and the existing encoder add allocations. This is not a 16 MiB process cap.
The external 4 MiB framing/queue contracts are unchanged. Package, unsupported
and concurrent E behavior is conservative B fallback; release aggregate
admission, long-soak growth and per-platform memory budgets remain unqualified.

## Selection, provenance and remaining work

The original [RSP-100 acceptance](rust-performance/TODO.md#rsp-100-reuse-request-local-risk-analysis)
requires categories/signals once for unchanged exact inputs and recomputation
after authority/catalog/input changes. E demonstrates a private lifetime that
can meet that computation rule and actual forwarding proof in its tested
selected scope. The retained product default still uses two analyses; package
rewrite and broader admission/shape coverage also remain outside the candidate.
Keep RSP-100 OPEN. Its previous ownership audit's proposed design is now
implemented and measured as E, not still an unattempted suggestion.

[PRD section 6](rust-performance/PRD.md#6-proposed-acceptance-targets) requires a
selected hot tranche to improve p95 or tree CPU by at least 30%, with no more
than 5% regression in the other primary metric. This campaign supports no
general E activation. A future narrow selection would need a declared actual
input distribution and selection rule, stable same-route nonregression,
portability/admission decisions and the remaining original qualification work.
It must keep the forwarding proof and public mutation semantics. This bounded
attempt ends with the measured result; it does not remove validation to chase
CPU or claim that exact private preparation is impossible.

RSP-098/RSP-103's completed source measurements and the previously recorded
conditional native RSP-104–108 decisions remain unchanged. All C/D/native
negative data remain frozen. E neither ships a native kernel nor supplies
installed Linux/macOS/Windows gates, confidence intervals, 10,000 warm decisions,
100 cold starts/recoveries, concurrency or soak qualification.

Both source arms use Python 3.12.14 on the shared Linux x86_64 host. B source is
on observed overlay device 28; E source and both arms' fixture stores are on
tmpfs device 27. No existing source, executable or cache was relocated. Startup
is not qualified across those source filesystems, and no absolute result is
aggregated with the previous campaigns' different fixture placement. Host quota
was eight CPUs with nine visible logical CPUs and 20 GiB cgroup memory limit.
The single host-load observation (1.945/2.476/2.799) was taken at 15:16:54.417366
UTC. The later full-source environment timestamp 15:19:01.303228 marks export
provenance; it copied that earlier host/Python observation. Both original files
remain unchanged, with this distinction recorded in the decision metadata.
