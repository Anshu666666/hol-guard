# Common workload and per-artifact semantic evidence

The paired installed runner distinguishes the common experiment inputs from
the semantic scope observed on each artifact. This permits comparison of the
same inline timing workload when one artifact cannot perform a separate source
reference operation. It does not make a source refusal equivalent to a full
content review.

`common_workload_digest` commits to the sampling plan, ordered daemon routes,
allowed timing series, frozen corpus manifest and oracle digests, explicit
normal policy, and the actual shared synthetic daemon, direct-native, and
registered-launcher input definitions. The launcher cold state is explicitly
`fresh_launcher_process_resident_prepared`. Artifact identity, capabilities,
observed coverage, and results are excluded from this common input identity.
The existing `corpus_digest` field remains an alias; the controller requires
both fields and rejects disagreement. Older evidence without the explicit new
identity is not silently reinterpreted.

`semantic_scope_digest` separately commits to the observed matrix and validated
daemon/launcher case identities. It must remain stable across blocks within
each artifact. Baseline and candidate may have different semantic scope
digests. Each block retains its full corpus, capability-derived platform scope,
and validation results.

The current 38 timing series comprise 21 inline daemon routes, one direct
native client route, 12 registered priority-launcher series, native cold start,
recovery, policy readiness, and full daemon startup. The controller accepts
only the declared inline/process series. Source reference timings and
instrumented side scenarios cannot enter these ratios through an unexpected
numeric series name. Adding such timings requires an explicit equivalence
contract and an updated workload definition.

For the pinned Windows baseline, the corpus preserves 55 source-reference
denial cases and leaves full reference review unqualified. A candidate that
advertises the verified handle-reader capability must satisfy the original
content and identity expectations. `reference_comparability` retains both
arms' observed contract status and reports semantic comparability only when
every block of both arms demonstrates full review. Reference timing
comparability remains false because this plan does not time that boundary.
The existing paired `reference_full_review` acceptance gate is unchanged;
candidate success cannot manufacture baseline support.

This identity correction does not alter sample minima, latency ceilings,
process-tree CPU requirements, artifact checks, hardware matching, failure
retention, or program qualification. Synthetic tests cover actual generated
Windows corpus inventories, changed timed bytes and sampling plans, common
input drift, per-arm scope drift, refusal-timing injection, privacy-safe
round trips, and retained unavailable CPU/full-reference gates. These tests
do not establish installed Windows source review or performance qualification.
