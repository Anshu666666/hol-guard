# Native edge refusal diagnostics

The installed Linux candidate at `9db62e8844c2ba2627f55b6b00e58cb5b175185d` returned no native edge for `cursor.afterShellExecution.empty-output.empty`. The actual worker took 5.321 ms, retained 2,985.196 ms of its caller budget, had a valid generation and cached publisher ACK, and observed no client failure code before or after the call. Those facts do not identify the refusal: a client can return an error object that the edge decoder rejects without setting the transport failure context.

The private fixture now observes the values already returned by the existing runtime-status, envelope, client, decoder, receipt and resident-failure functions. Each original call runs exactly once. No request bytes, raw response bodies, paths or unrestricted error text are retained. Known errors use the existing finite native vocabulary; unknown text produces only a bounded digest. A per-worker ContextVar separates concurrent observations, and nested fixture lifetimes share one wrapper installation until all owners exit.

Stage facts are flattened into `edge_<stage>_<field>` entries within the existing native-call diagnostic. This preserves the unchanged privacy depth in both source-witness and capacity failure exports. A complete source-witness failure is sanitized and JSON-round-tripped in the regression; the decoder error, boolean decision and call count remain scalar values rather than truncation placeholders.

The Claude pilot resets diagnostic capture before each launch, outside that launch's latency timer. Its daemon CPU accounting includes the per-attempt control reset and stage-observation overhead in both arms; it must not be pooled with the previous pilot campaign. A child that fails before daemon ingress receives zero native calls rather than the previous child's trace. Preflight failures retain their arm, event and case and are excluded from measurements. Failed series retain partial launch latency/CPU, sampled daemon resources, route counts and closed native/delivered semantics, always excluded from comparison.

The `9db` pilot remains incomplete. Its first Python and native PreToolUse cells each completed 30 launches. The Python PostToolUse cell then attempted 11 and completed 10 before an unexpected delivered reason. No full five-block comparison or activation follows from those partial observations. The stage additions do not change that retained attempt or explain it retrospectively.

The final focused validation passed **83 tests in 5.86 seconds**, Ruff and formatting for nine changed Python files, and type analysis of all six changed scripts with **zero errors** (217 nonfatal warnings). The [source-bound validation record](evidence/native-edge-stages-validation.json) retains commands, hashes and earlier source-validation failures. Independent review found and corrected the nested export depth, per-attempt attribution and preflight coverage gaps. No local native-host or performance execution is claimed.
