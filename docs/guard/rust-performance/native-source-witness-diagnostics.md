The fixture now uses `scripts/native_slo_native_diagnostic.py::observe_native_call` inside the existing worker wrapper. It calls the original operation exactly once, returns the identical object, and propagates its exception unchanged. Immediately after the operation returns, it reads `native_resident_client_failure_code` in that same context. The getter is a ContextVar: reading it later in the collector thread can miss the worker's value. A before value is also retained, because early edge failures need not enter the client and an unchanged code may belong to a previous call. The helper does not clear or overwrite that context.

The bounded diagnostic contains finite client labels or a digest only, relative caller-deadline/elapsed milliseconds, supplied policy-binding shape, and cached publisher ACK/closed/started/snapshot/error fields. Values outside the finite code vocabulary never become raw report text; overlong values use a bounded prefix digest with `digest_complete=false`. Publisher metadata uses a nonblocking lock attempt and reports `busy` when unavailable. It never calls runtime-health or publisher-readiness getters: those APIs can refresh circuit/expiry state or create cache entries. Cached flags are observations, not a fresh readiness or policy-acceptance claim. The caller deadline is reported without replacing the native client's existing internal budget semantics, including its setup-time accounting.

The source witness still requires one Rust allow, `allow_original`, the exact expected review digest, and an existing complete-scan reason. Diagnostics are attached only to its existing bounded failure observations; they do not permit an availability allow to qualify, change a timeout, trigger recovery, or issue another native request. The paired-corpus wrapper can reuse the same helper independently. Original artifacts and acceptance thresholds remain unchanged.
