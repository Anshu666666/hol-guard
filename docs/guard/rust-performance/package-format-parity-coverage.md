# Package format parity and malformed-input coverage

This RSP-059 audit starts from source `6c6d7a2cb6af6d0541bd8ddef163bbb854e2a8d0`. It adds Python evaluator correctness coverage and corrects two demonstrated defects. The coverage below addresses the original criterion's named supported behaviors; it does not implement RSP-058, qualify a native parser, or change the [release decision to retain optimized Python](package-native-selection-decision.md). The original [TODO criterion](TODO.md) and dependencies remain unchanged.

## Corrections and identity

A `Gemfile.lock` containing `GEM`, `specs:`, a valid `demo (1.0.0)` row and then a four-space `unfinished (` row previously returned `complete=True` with the first dependency. The parser ignored the malformed row. It also treated an indented uppercase unfinished name as a section heading. Every nonblank, noncomment four-space row inside a recognized specs block must now match the supported complete `name (version)` form; malformed or unsupported rows invalidate every projection with `syntax_error`. This also rejects invalid-name and colon-form rows instead of silently omitting them. Only unindented section headings end a specs block. Nested dependency constraints, GEM/GIT/PATH sections, platform suffixes, prereleases and last-write duplicate handling retain their existing behavior.

The parser identity advances from **`complete-v2` to `complete-v3`**. A real stored allow bound to v2's approval content identity is rejected under v3 with `approval_reuse_content_changed`; the existing future-version regression remains. The benchmark protocol admits the closed historical v1/v2 and current v3 values, and rejects unknown future values. No retained v1/v2 evidence or measurement has been rewritten or relabeled as v3. This malformed-input admission correction intentionally differs from the old permissive extractor.

Targetless `bun install` also previously read `bun.lockb` and passed it to the text parser while deriving manifest dependencies. That path now skips the binary file before its retained-content read, matching completeness collection and direct/transitive extraction. Both targetless and named-target requests retain the explicit binary fallback: balanced mode asks, strict/paranoid modes block. Tests prohibit both a binary content open and a text-parser call during evaluation; this adds no binary-format support.

## Boundaries that remain open

This is a finite source correctness corpus, not exhaustive syntax conformance. The [supported text grammar](../rsp-text-lockfile-contract.md) still excludes non-root pnpm direct importers, optional-only snapshot fallback records and legacy slash-only keys from its manifest view. Unknown sections and nested Bundler dependency constraints are not promoted into a general Bundler grammar validator. Complete-v3 tightens recognized top-level spec admission only. The unchanged 8 MiB / 100,000 entries per view / 250,000 nodes / depth 128 and cooperative deadlines still apply.

The literal RSP-059 criterion enumerates source-test themes, without requiring an exhaustive Cartesian matrix or an installed timing qualification. This audit establishes each named theme for the supported Python behavior and recommends closing that source-test criterion after integration and independent review. The RSP-058 dependency remains recorded and its native implementation remains conditionally deferred. These tests do not establish Python/native format parity, all manager-version/workspace layouts, or full lifecycle/installed acceptance. Prior baseline Composer failures and cardinality censoring remain in their original cohorts.

The final focused run passed **265 tests**, including all **49 new format cases**, existing text/structured completeness and single-parse regressions, exact saved-approval rejection and the finite worker protocol. A preceding broader source run passed 455 tests, including local/git/Composer/JS/Python/tier2 behaviors; independent review then added the final misplaced-specs-marker regression and the focused run was repeated. Scoped production/protocol BasedPyright reported zero errors (77 existing strict warnings), and Ruff/format/diff checks passed. The review identified and closed both the indented-uppercase heading escape and the misplaced specs marker. No performance matrix, local timing experiment, remote mutation or release activation is part of this change.
