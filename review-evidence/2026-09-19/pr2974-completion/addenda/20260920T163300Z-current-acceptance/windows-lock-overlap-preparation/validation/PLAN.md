# Windows journal byte-lock overlap contract

This separate source-only experiment uses exact ad9d journal product bytes. It does not repeat the corpus, modify product code, or identify the historical journal permission event. The prior one-shot journal observer returned21 native receipts and zero journal events, while retaining a distinct command activity sqlite_busy event with no extended-code/operation attribution.

Five independent real Windows cells run once: original uncontended; original with another process holding the original journal lock; original after that holder released; same-open/same-guard nonblocking CRT exclusion under a held lock; same-open/same-guard unchanged LK_LOCK under a held lock followed by release. The primitive controls omit truncation deliberately to isolate it; they are not product fixes or installed qualification. Each holder enters the actual original _journal_lock, and each contender opens its own descriptor. Original O_CREAT/O_RDWR/CLOEXEC/NOFOLLOW flags, mode0600, same-handle regular/single-link guard, private-mode helper, byte0 offset/range and unlock/close ordering are retained. No new explicit Windows DACL/owner proof is claimed.

The original held cell strictly requires successful serialization and entry. A pre-lock ftruncate error remains a failed product contract, with the original finite exception class/errno/winerror and exact failed operation retained. No presumed native code is required. The separate nonblocking cell establishes actual exclusion; a250ms no-completion observation before release is only observed scheduling/order, not proof of how long an unscheduled contender blocked. The blocking primitive remains LK_LOCK with its existing CRT behavior. No timeout, retry or permission change is made to product.

Twenty-one portable controls cover exact one-call forwarding and exception identity, real descriptor closure, original failure before acquisition, original close-error retention versus separate emergency retirement, callback restoration, finite error/privacy schema, duplicate JSON keys, malformed child output, actual direct-child kill/reap, and spawn failure. Five native cells are skipped locally and must all execute on Windows. The driver binds26 unique JUnit identities/count and all five named reports; failures stay failed. It does not independently compare a collection roster.

All child output is a fixed schema with bounded frames/bytes and no payload, arbitrary message, path, descriptor number or SID. Unexpected stderr is suppressed, so a missing child result is an explicit diagnostic failure with return/retirement facts, not reconstructed traceback attribution. Each process creates no further child. The controller records direct process reaping and reader-thread join; its outer subprocess timeout does not itself prove descendant cleanup.

Source is four added diagnostic/control files, sole-parent ad9d. Driver is one added workflow. Pinned Python3.12.10, uv0.9.26 and frozen project dev dependencies; no Rust/native build. Static gates precede one26-case invocation; original failure XML/logs and before/after bindings always upload. Only source/tree/branch placeholders may be substituted.
