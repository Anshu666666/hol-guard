The old [syscall parser](https://github.com/hashgraph-online/hol-guard/blob/67d90ff0211dbc1d878499b90eecb126da98b7fb/scripts/probe_sqlite_syscall_observation.py) rejoins unfinished/resumed records in completion order. Its accepted descriptor witness is serial and uses two disposable control files. The old trace filter does not cover complete process or FD-table lifetimes or bind each SQLite I/O event to a live inode. Extending those completed-call records into a concurrent FD ledger would therefore be unsound. A renamed path or an after-the-run stat cannot repair the missing event-time association.

The new control observes only one owned single-thread child. Before tracing begins, the collector exclusively creates two mode 0600 files beneath one owned mode 0700 directory and retains their fstat identities. The child inherits those descriptors; the collector closes its own file descriptions before the admitted interval. This explicitly bounds the initial descriptor inventory rather than claiming that creation/open events were observed.

The collector uses PTRACE_TRACEME, PTRACE_SYSCALL and PTRACE_GET_SYSCALL_INFO. It accepts exactly twelve syscall entry/exit pairs, one exit_group entry, a matching exit event and actual child retirement. The only optional prefix is the separately recorded zero-return exit of the fixed SIGSTOP bootstrap. Unknown syscalls, extra thread/process events, signals, seccomp stops, ABI mismatches, short syscall-info records and incomplete pairs refuse the result. Ptrace controls individual threads; this design intentionally has no concurrent thread or FD-table sharer. [Linux ptrace API](https://man7.org/linux/man-pages/man2/ptrace.2.html)

At each relevant entry stop, pidfd_getfd temporarily duplicates the tracee descriptor and fstat binds its live backing device/inode to the owned fixture. The duplicate is closed before the sole tracee resumes. No buffer read, offset change, flag change or sync is performed through that duplicate. Permission denial or unsupported pidfd/ptrace operations remain explicit refusals; there is no pathname-stat or strace fallback. pidfd_getfd itself is subject to a ptrace access check, so old strace success does not establish this gate. [Linux pidfd_getfd API](https://man7.org/linux/man-pages/man2/pidfd_getfd.2.html)

A matching inode does not by itself establish a shared open-file description. Here that relationship follows from the observed successful dup/dup2 operation, its known input descriptor and its verified returned descriptor in the sole tracee. The later fixed-content check also verifies the expected shared offset after the A alias survives reuse of the old descriptor number for B. That after-retirement readback is corroboration only: event counters never come from a later stat, file length or path lookup.

| Operation interval | Required evidence |
| --- | --- |
| Write 9 bytes through A; dup A; fsync its alias | A's live descriptor identity, observed successful syscall results and a separately bound returned alias |
| Close the original A descriptor; dup2 B into that number | The original lifetime closes, the target is actually EBADF before dup2, and the resulting descriptor binds to B |
| pwrite 11 bytes to B at offset 7; fdatasync B; close it | B identity at each relevant entry and the exact observed results |
| fsync the now-closed nonnegative descriptor | Actual pidfd_getfd EBADF and syscall-return EBADF; permission denial cannot stand in for this control |
| Write 5 bytes through the surviving A alias; close alias and B's other descriptor | The alias still binds to A, all twelve pairs finish and every admitted descriptor lifetime closes |

If the future run passes, its finite result will be fourteen syscall-return payload bytes for A, eleven for B, one successful fsync, one successful fdatasync and one failed sync. These are expected control values until actually executed. B's file length will be eighteen because of its offset 7 hole; the decoder cannot substitute that length for the eleven returned write bytes. A successful write return can be partial and is not a physical-device byte measurement; the fixed control refuses unexpected partial results rather than extrapolating them. [Linux write API](https://man7.org/linux/man-pages/man2/write.2.html)

The control does not measure SQLite transactions, WAL/database rewrites, queue age, the installed daemon, native hook receipts or physical storage writes. Successful sync calls are counted separately from failures; no directory-sync or device-level durability claim is inferred. [Linux fsync API](https://man7.org/linux/man-pages/man2/fsync.2.html)

Every output record has a bounded size and monotonic sequence number. The C collector has a 64-record limit and six-second inner deadline. Its nonblocking output writer refuses short writes or output saturation. The Python wrapper reuses the exact unchanged prior supervision implementation: an eight-second command deadline, 256 KiB per stream, WNOWAIT PID reservation, owned-group cleanup, stream-completion checks and explicit reader retirement. The source work does not change those existing bounds. A terminal record alone is insufficient: the decoder also requires the launch PID binding, exact event grammar, complete capture, zero unexpected stderr, successful direct-child and owned-group retirement, inode-bound identities and the fixed readback. Missing pairs, reordered or extra events, censored streams, output loss, unknown aliases and non-retirement yield null measurement fields.

The workflow is bounded to six minutes, with a two-minute combined compiler/control step. Each compiler or control subprocess independently retains the existing eight-second supervision limit plus its bounded retirement. Artifacts contain normalized JSON, fixed metadata-only call records, source/tool/environment bindings, finite case outcomes and hashes of retained compiler/test logs. The source checkpoint creates no branch/ref and launches no workflow.

A passing first run would establish only this finite prerequisite. A genuine concurrent SQLite collector still needs all of the following before an installed campaign can count:

- A complete process/thread generation and FD-table model, including fork/clone/CLONE_FILES, exec/CLOEXEC, unshare, dup/fcntl duplication, close/close_range and every SQLite I/O path actually used. Each successful open creates its own lifetime identity; equal inode numbers cannot merge independent open-file descriptions. Unmodelled mmap, asynchronous I/O or alternate write paths must refuse coverage.
- Event-time binding after the kernel has selected the actual file object, or a proved boundary stopping every relevant FD-table sharer until descriptor selection. A temporary duplicate pins an open-file description but does not stop another thread from reusing the numeric FD. Completion-order reconstruction cannot solve this race. Linux permits an in-flight I/O to retain its old open-file description after a concurrent close, and failed close calls require careful lifetime handling rather than blind retry. [Linux close API](https://man7.org/linux/man-pages/man2/close.2.html)
- Explicit loss/overflow and start/end admission from the selected collector, complete entry/exit pairing and process retirement, and a refusal when required kernel events or process generations cannot be accounted for. User-space sequence numbering by itself cannot prove that an arbitrary concurrent kernel event source lost nothing.
- A separately admitted, already available kernel observation facility if ptrace serialization perturbs the intended workload. A matched-kernel file-object probe could observe the real VFS object after descriptor resolution, but the previously inspected environment lacks the required admitted capabilities. This checkpoint neither enables that facility nor substitutes an unsupported fallback.
- Actual installed native receipts alongside mixed pre/post hooks and policy updates, transaction/file-lifetime correlation, lossless reconciliation, queue-age measurements and complete process-tree resources. Batch writes must not be presented as one fsync per receipt without evidence. Instrumented observation must retain its overhead limits and remain separate from the existing uninstrumented latency gates.
